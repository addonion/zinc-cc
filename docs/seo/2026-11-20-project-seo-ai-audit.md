# Аудит zinc.cc на 20 ноября 2026 года

Первый приоритет — обновление Next.js с исправлениями безопасности. Для поискового и ИИ-продвижения стоит начать с трёх содержательных кейсов в портфолио и измерить, появились ли у этих страниц показы. Все 56 адресов из карты сайта доступны, а все 50 карточек проектов содержат галереи без текстового описания работы. [Карта сайта](https://zinc.cc/sitemap.xml), [портфолио](https://zinc.cc/portfolio-intereri/)

## Зависимости и сборка

Логи текущего production-развёртывания Vercel показывают коммит `951ac4c` и Next.js `16.4.4`. На этой версии `npm run lint` проходит, а `npm run build` генерирует страницы и завершается с `SecurityFatalError`. `npm audit` вернул 10 затронутых пакетов уровня moderate. В списке есть Next.js, в том числе advisory для оптимизатора изображений. Это проверка версий и сборки. Применимость отдельных сценариев к сайту не проверялась. [Релиз Next.js 16.4.6](https://github.com/vercel/next.js/releases/tag/v16.4.6), [advisory Next.js](https://github.com/advisories/GHSA-7qx7-33qx-rqx2)

В отдельной временной копии после чистого `npm ci` через npm `11.17.0` прошли `npm run lint` и `npm run build`, а `npm audit` вернул 0. При установке были предупреждения о peer-диапазонах плагинов `eslint-plugin-import`, `eslint-plugin-jsx-a11y` и `eslint-plugin-react` для ESLint 10. Источники версий и аудита — npm registry и `package-lock.json`.

Vercel проигнорировал настройку `22.x` и выбрал `26.x` из-за открытого диапазона `engines.node: >=20.9.0`. Для воспроизводимости предлагаю закрепить `24.x` и согласовать его с настройкой Vercel и типами Node. Обновлённые зависимости проверены на локальной `24.19.0` с `engines.node: 24.x`. При публикации проверить версию в новых логах и выдачу главной, контактов, портфолио и 3D-тура. Для локального запуска полезно заменить шаблонный README короткой инструкцией с `SERVER_HOST` и `npm ci`. [Правила выбора версии Node.js в Vercel](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions), [статус Node.js LTS](https://nodejs.org/en/about/previous-releases)

## Техническое SEO

- **HTTP-проверка прошла.** В sitemap 56 уникальных URL, из них 50 проектов. Все возвращают `200`, у каждого один H1, самоканонический URL, уникальные `title` и `description`, JSON-LD и `og:image`. Все 50 проектов связаны ссылками со страницы портфолио. Все 51 уникальное изображение из `og:image` ответило `200` на `HEAD`. У картинок из галерей уже есть адаптивные варианты. [Карта сайта](https://zinc.cc/sitemap.xml), [портфолио](https://zinc.cc/portfolio-intereri/)
- **Проверенные редиректы работают.** HTTP и `www` ведут на основной домен, `/about/` — на главную, `/portfolio-intereri/qwe/` — на «ЖК Новый центр». Несуществующие маршрут и проект отдают `404`. Главная с UTM указывает canonical без параметров. Для старых `.html` имеет смысл добавлять точечные редиректы только там, где найдено соответствие новому проекту и есть внешние ссылки либо трафик. [Google о канонических URL](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- **Вебмастер показывает 39 страниц в поиске** на экране «Мои сайты», где Яндекс предупреждает о приостановке обновления данных. У `/portfolio-intereri/lionhouse/` есть запись от 17.11 с обработкой данных о каноническом URL. На сводке также есть предупреждения про дубли и отсутствующие теги, но среди 56 проверенных текущих канонических URL такие случаи не воспроизвелись. Выгрузка дублей недоступна, поэтому конкретные адреса из предупреждения не установлены. [Страницы в поиске](https://webmaster.yandex.ru/site/https:zinc.cc:443/indexing/searchable/), [отчёт о заголовках и описаниях](https://webmaster.yandex.ru/site/https:zinc.cc:443/indexing/double-descriptions/)
- **Google Search Console запросила повторный вход.** В историческом срезе от 13.11 было 6 проиндексированных страниц, среди показанных примеров не было отдельных кейсов, а отчёт о sitemap показывал 33 обнаруженных URL и старую дату чтения. Свежий статус не подтверждён. После входа сравнить отчёт о sitemap с 56 текущими URL и проверить выбор canonical и дату обхода для трёх приоритетных кейсов через «Проверку URL». [Индексация в Search Console](https://search.google.com/search-console/index?resource_id=sc-domain%3Azinc.cc), [справка по sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- **Риск при сбое CMS.** В `app/sitemap.ts` ловится любая ошибка Strapi и возвращается пустой список проектов. Если это произойдёт при генерации XML, sitemap может отдать `200` с шестью страницами вместо 56. На сайте это сейчас не наблюдалось. Стоит сохранить последнюю успешную карту при временном сбое и добавить проверку числа URL после деплоя. Для `lastmod` использовать даты содержательных изменений. Google игнорирует `priority` и `changefreq`. [Правила Google для sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

## Что улучшить для поиска и ИИ-ответов

1. **Превратить три галереи в кейсы.** Для начала подойдут «ЖК Вознесенский», «Дом со львами» и «Реализация коттеджа в Протасах». Внести в Strapi подтверждённые студией факты о типе объекта, городе, площади, задаче, ограничениях и решениях. Для реализованных объектов описать, что сделано, добавить авторство и указать статус. Вывести эти сведения видимым серверным HTML рядом с галереей, добавить короткое уникальное описание для сниппета и ссылку на услугу. В проверенном HTML у всех 1005 фотографий галерей найден шаблонный alt «название проекта — фото N». Начать с уникальных описаний обложек и ключевых кадров в трёх кейсах. [Google AI Search](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [Google Images](https://developers.google.com/search/docs/appearance/google-images), [Яндекс о выборе источников](https://yandex.ru/support/webmaster/ru/alice)
2. **Уточнить главную и локальные сведения.** Сейчас title главной сфокусирован на домах и коттеджах, H1 — на дизайне интерьера в Перми вообще, а первые абзацы CMS дают общее объяснение дизайна. Добавить в начало понятное описание студии, услуг в Перми, состава первой встречи, 3D-тура и ссылки на релевантные проекты. Перед сменой title или запуском `/dizajn-doma/` сравнить, по каким запросам главная уже получает показы по домам и коттеджам. Сверить адрес, телефон, ссылку, фотографии и часы приёма с существующей карточкой Яндекс Бизнеса, если она есть. Доступ к карточке в этом аудите не проверялся. [Главная](https://zinc.cc/), [контакты](https://zinc.cc/contacts/), [Яндекс Бизнес](https://yandex.ru/support/business-priority/ru/add-company/add-org)
3. **Зафиксировать видимость и переходы.** В отчёте Zinc «Видимость сайта в Алисе AI» за 17.08–15.11 показано «Пока недостаточно данных» и предупреждение о задержках. В Google проверить статус участия и отчёт Generative AI после входа. В Метрике считать переходы по фактическим реферерам и UTM на хосте `zinc.cc`. В срезе от 16.11 за совпадающий период было 29 кликов Google и 1 поисковый визит Метрики. Стоит проверить фактическую загрузку счётчика, разрез по страницам входа и реферерам, а для цели «заявка» сверить, что измеряется. Через 28 дней после публикации пилотных кейсов сравнить их индексирование, показы, переходы и целевые действия с базовым периодом. [Отчёт Zinc в Алисе AI](https://webmaster.yandex.ru/site/https:zinc.cc:443/efficiency/alice/), [методика отчёта Алисы](https://yandex.ru/support/webmaster/ru/service/alice-answers), [показы Google AI](https://support.google.com/webmasters/answer/16984139), [управление участием](https://support.google.com/webmasters/answer/16908024), [атрибуция Метрики](https://yandex.ru/support/metrica/ru/general/sources-tracking)

Текущий `robots.txt` разрешает обход публичных страниц. Главная и «Дом со львами» вернули `200` с HTML при запросах с названиями Googlebot, YandexBot, YandexAdditionalBot, OAI-SearchBot, GPTBot, bingbot и PerplexityBot в User-Agent. Это проверка ответа с одного клиента. Запросы с официальных IP и реальные цитирования не подтверждены. Для ChatGPT Search важен `OAI-SearchBot`. `GPTBot` управляется отдельно и относится к обучению. Google Search игнорирует `llms.txt`, включая поиск с генеративными ответами. Для Zinc выше приоритет у кейсов, индексации и измерения. [robots.txt](https://zinc.cc/robots.txt), [боты OpenAI](https://developers.openai.com/api/docs/bots), [боты Яндекса](https://yandex.ru/support/webmaster/ru/adding-site/indexing-prohibition), [боты Perplexity](https://docs.perplexity.ai/docs/resources/perplexity-crawlers), [позиция Google о llms.txt](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
